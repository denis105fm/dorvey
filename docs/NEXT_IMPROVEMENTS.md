# Что ещё улучшить и добавить

Краткий приоритизированный список по направлениям.

---

## 1. UX: настройки конверсии без JSON ✅

**Реализовано.** В кампаниях — кнопка «Конверсия»: форма с полями Urgency, Social proof (статистика + 3 отзыва), Exit-intent (заголовок, текст кнопки), CTA desktop/mobile. Сохранение в `affiliate_rules.settings` через `PUT /api/rules/campaign/{id}/conversion`.

---

## 2. Wizard первого запуска ✅

**Реализовано.** При отсутствии кампаний показывается пошаговый визард: (1) Создать кампанию (название + affiliate URL), (2) Домен — пропустить или перейти в Домены, (3) Ключевые слова — пропустить или в Ключи, (4) Готово → «Перейти к дорвеям». Закрытие по «Позже» или после шага 4 сохраняется в localStorage.

---

## 3. Сравнительная таблица из офферов

**Проблема:** comparison_table в шаблоне есть, но строится из AI/контента. По офферам кампании таблицу не строим.

**Идея:** если у кампании есть офферы с полями (название, ставка, сумма, срок) — рендерить блок «Топ-N офферов» с CTA. Либо новое поле в Offer: name, rate, amount, term — и в deploy строить таблицу из них.

**Эффект:** больше доверия и конверсии за счёт сравнения.

---

## 4. Редактор шаблонов в UI

**Проблема:** шаблоны создаются/редактируются только через API.

**Идея:** страница Templates — не только список, но и создание/редактирование: имя, тип, тело шаблона (textarea или простой редактор), переменные из доки.

**Эффект:** менять верстку/тексты без API и доков.

---

## 5. PAA/FAQ из AI в cloaking_rules

**Проблема:** FAQ/PAA schema можно задать вручную в `cloaking_rules.faq_qa`. Генератор не заполняет это сам.

**Идея:** в генераторе дорвея (или отдельный шаг «Сгенерировать FAQ») — запрос к AI: «Сгенерируй 3–5 вопросов-ответов по теме keyword»; результат класть в `cloaking_rules.faq_qa` и подставлять в шаблон.

**Эффект:** богатые сниппеты и PAA без ручного ввода.

---

## 6. Алерты и лимиты

**Проблема:** алерты по аномалиям есть (cron, webhooks), но нет явных лимитов «дорвеев/кампаний» и уведомлений при достижении лимита.

**Идея:** в Billing/Settings — лимиты по плану; при создании дорвея/кампании проверять лимит; при достижении 80%/100% — событие в webhooks (например `billing.near_limit`) и при желании Telegram/Email.

**Эффект:** контроль расхода и предсказуемость.

---

## 7. Автоприменение рекомендаций

**Проблема:** рекомендации AI показываются в UI, но применение — вручную.

**Идея:** в Rules кампании — опция `auto_apply_recommendations: true` и пороги (например CTR/CR ниже X%). Cron при падении метрик вызывает apply_recommendation по заданному правилу.

**Эффект:** меньше ручной работы, быстрее реакция на просадки.

---

## 8. Небольшие улучшения

- **Поиск/фильтр по домену** на странице Дорвеи (сейчас фильтр по кампании и общий поиск).
- **Копирование cloaking_rules** с одного дорвея на другой (или «применить настройки с победителя»).
- **Экспорт/импорт кампании** (JSON/YAML) — бэкап и перенос между инстансами.
- **Графики в Analytics** — показы/клики/CR по дням (сейчас в основном суммарные цифры).
- **Проверка SSL** по домену в списке доменов (истекает через N дней).
