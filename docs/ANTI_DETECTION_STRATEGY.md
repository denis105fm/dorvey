# Стратегия снижения риска блокировки

> Как максимально избегать попадания под алгоритмы и фильтры поисковиков.

Google не ищет слово «дорвей» — он ищет **паттерны низкой ценности и манипуляции**. Даже «умные» варианты оставляют следы. Ниже — по слоям: что детектируется и как мы это смягчаем.

---

## 1. Семантический анализ

**Что делает поисковик:**
- Embedding-модели, анализ смысла, сравнение тематики
- Оценка полноты ответа и закрытия поискового намерения

**Сигналы, которые бьют:**
- Страница не закрывает intent
- Поверхностный контент
- Повторяющиеся общие фразы
- Отсутствие уникальной ценности

### Меры в Dorvey

| Действие | Реализация |
|----------|------------|
| Глубина контента | AI-генерация с минимальным объёмом (e.g. 800+ слов), промпты на полноту ответа |
| Интент-чеки | Проверка соответствия title/content/keyword перед деплоем |
| Уникальность | Избегаем шаблонных фраз, добавляем контекст региона/локали |
| PAA / FAQ | Реальные ответы на «People Also Ask», не generic-списки |

---

## 2. Поведенческие сигналы

**Что делает поисковик:**
- Pogo-sticking (быстрый возврат в поиск)
- Время на странице
- Глубина просмотра
- Взаимодействие (клики, скролл)

**Сигнал:** массовый «отскок» = страница не удовлетворяет запрос.

### Меры в Dorvey

| Действие | Реализация |
|----------|------------|
| Задержка редиректа | Редирект только после взаимодействия (клик CTA), не мгновенный |
| Exit-intent | Окно «Подождите!» — удерживает, увеличивает время на странице |
| Содержание до CTA | Основной контент до кнопки, не «пустая» страница |
| Core Web Vitals | Быстрая загрузка → меньше bounce по техническим причинам |

---

## 3. Структурные footprint’ы

**Что делает поисковик:**
- Сравнение DOM, порядка блоков
- Одинаковая микроразметка, шаблонные FAQ
- Технические паттерны

### Меры в Dorvey

| Действие | Реализация |
|----------|------------|
| Варианты layout | Несколько структурных шаблонов (A/B), рандомный выбор при рендере |
| Порядок блоков | Trust, FAQ, CTA в разном порядке (seed от URL/hash) |
| Микроразметка | Вариативность schema: Article vs WebPage, порядок полей, опциональные поля |
| Классы/CSS | Разные class-префиксы и минимальная «отпечатывающая» структура |

---

## 4. Инфраструктурный анализ

**Что делает поисковик:**
- IP, ASN
- DNS-паттерны
- Одинаковые серверные сигнатуры
- Массовая регистрация доменов
- Синхронные публикации

### Меры в Dorvey

| Действие | Реализация |
|----------|------------|
| Stagger deploy | Разброс по времени: не деплоить 50 страниц за минуту |
| Разные серверы | Рекомендация: разные хосты/ASN для разных кампаний |
| Лимиты | Ограничение частоты индексации (GSC URL submission) |
| Случайная задержка | `deploy_delay_min/max` — пауза между деплоями в batch |

---

## 5. Ссылочный граф

**Что делает поисковик:**
- Кто ссылается
- Откуда трафик
- Распределение анкоров
- Кластеры сетей

### Меры (вне платформы, рекомендации)

- Разнообразие анкоров
- Избегать перекрёстных ссылок внутри сети
- Не делать массовый линкбилдинг на дорвеи

---

## 6. ML-антиспам модели

**Что делают:**
- Обучаются на выявленных сетках
- Ищут корреляции по сотням сигналов

**Вывод:** Невозможно «обмануть» вручную. Снижаем **статистический шум** и **масштаб синхронности**.

---

## Практические алгоритмы в Dorvey

### A. Structural randomization

- При рендере страницы: seed = `hash(domain + path + doorway_id)`
- Выбор layout-варианта (1..N)
- Порядок блоков: trust, FAQ, comparison, CTA — перетасовка
- Trust badges: 3–5 вариантов текста, случайный выбор

### B. Deploy staggering

- Batch deploy: между каждым деплоем пауза `random(deploy_delay_min, deploy_delay_max)` сек
- **Рекомендации:** min 30 сек, max 5 мин для больших батчей (настраивается в конфиге кампании/сервера)
- Cron: задачи Celery Beat в 3:00 и 4:30 — разнесены по времени

### C. Content quality checks (pre-deploy)

- **Минимальная длина content** — 400 символов (MIN_CONTENT_LENGTH), рекомендуется 600+; AI — 400+ слов
- **Title** — min 20 символов; meta description — 80+
- **Keyword alignment** — keyword должен быть в title и content
- **FAQ** — хотя бы 1 Q&A на интент (cloaking_rules.faq_qa)
- **Blacklist фраз** — ~22 шаблонные фразы (anti_detection.TEMPLATE_PHRASE_BLACKLIST)

### D. Analytics и обновления

- Мониторинг: позиции, CTR, bounce (если есть данные)
- Падение видимости → авто-пауза или алерт
- Рекомендация: раз в N дней пересматривать победителей и переносить паттерны на новые страницы

---

## Итог

**Цель:** не «спрятаться», а:
1. Давать **реальную ценность** (глубина, intent)
2. Улучшать **поведение** (время на странице, взаимодействие)
3. Снижать **структурное и инфраструктурное сходство**
4. Избегать **массовой синхронности** в масштабе
