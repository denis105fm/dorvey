# Внешние данные для аналитики офферов

Цель: повысить точность прогноза «оффер будет прибыльным» за счёт внешних сигналов (тренды по странам, новости, сезонность, рыночная статистика) в дополнение к нашим данным (CR, RPC, клики по офферу/гео).

## Подход к подключению

1. **Сначала — большие полные наборы**  
   Подключить один или несколько готовых источников с широким охватом (много стран, периодическое обновление). Данные кэшируются и используются в расчёте «прибыльности» и в рекомендациях по офферам/странам.

2. **Потом — дополнение**  
   По мере появления потребности или новых источников — добавлять ещё (отдельные API, выгрузки, ручные правила). Архитектура должна позволять подключать новые источники без переписывания логики.

3. **Подсказки в интерфейсе**  
   В Настройках (раздел «Внешние данные для аналитики офферов») перечислены рекомендуемые источники, что они дают и как подключаются (API key, URL, формат). Новые источники можно документировать там же и добавлять в код по мере реализации.

## Категории источников

| Категория | Что даёт | Примеры |
|-----------|----------|---------|
| **Рыночная/рекламная статистика по странам** | Тренды спроса, CPM/CPC по гео, объёмы по вертикалям | Открытые отчёты, партнёрские API (если есть), агрегаторы |
| **Новости и события по странам/нишам** | Регуляторика, запреты, сезонные события, инфоповоды | NewsAPI, RSS по странам, ручные теги |
| **Сезонность** | Календарь «сильных/слабых» периодов по гео и вертикали | Внутренний календарь + при желании внешние данные |
| **Регуляторика и ограничения** | Запреты по офферу/стране, возраст, лимиты | Текст из условий оффера (уже храним), при желании — внешние списки |

## Рекомендуемые источники (как подключать)

Ниже — приоритетные источники для первой реализации; полный перечень возможных см. в каталоге выше.

### 1. Новости по странам и темам (для контекста и рисков)

- **NewsAPI.org**  
  - Что даёт: заголовки/новости по ключевым словам и по странам (country).  
  - Как подключать: регистрация на newsapi.org → API Key → в настройках указать `news_api_key`.  
  - Ограничения: бесплатный тариф с лимитом запросов; по необходимости кэшировать ответы (например, раз в час по темам/гео).

- **Альтернативы**: GNews API, Mediastack, RSS-агрегация по странам (тогда источник — URL фидов, а не один ключ).

### 2. Большие готовые наборы по странам/рынкам

- **REST Countries / подобные API**  
  - Что даёт: базовые данные по странам (коды, регионы, языки). Используется для нормализации гео и привязки других сигналов к странам.  
  - Как подключать: обычно бесплатный API без ключа или с ключом; в настройках — опциональный URL или ключ, если нужен платный тариф.

- **Сезонность и календарь**  
  - Что даёт: помесячные/понедельные коэффициенты по странам или вертикалям (например, «декабрь — пик для подарков в US»).  
  - Как подключать: первый этап — свой JSON/таблица в коде или админке; позже — внешний API или файл (URL в настройках).

### 3. Дополнительные источники (подключать по мере появления)

- **Партнёрские/рекламные отчёты**  
  - Если есть доступ к API или выгрузкам по CPM/конверсиям по странам — добавить как отдельный источник с собственным ключом/URL в настройках.

- **Собственные выгрузки**  
  - CSV/JSON по странам (тренды, теги рисков). Загрузка файлом или URL с периодическим обновлением.

- **Ручные правила**  
  - Список «не запускать оффер X в странах Y» или «буст для оффера Z в гео W в период T». Хранить в настройках кампании или в общих настройках.

## Как это встраивается в систему

1. **Единый слой внешних данных**  
   Сервис(ы) в бэкенде: по запросу (оффер, страна, период) возвращают структурированные сигналы: тренд, сезонность, флаги риска из новостей, регуляторика. Внутри — обращение к подключённым источникам (по наличию ключей/URL в настройках), кэш, таймауты.

2. **Связка с нашими данными**  
   При расчёте «прибыльность оффера / оффер+страна» и при рекомендациях «какие офферы на неделю/месяц брать»:
   - используются наши метрики (CR, RPC, объём трафика по офферу и гео);
   - к ним добавляются внешние сигналы (тренд по стране, сезонность, риски из новостей);
   - результат: скор/рейтинг или бинарный «рекомендуем/не рекомендуем» с возможностью показа причин («сильный тренд в GE», «новости о запретах в RU»).

3. **Прозрачность**  
   В интерфейсе (дашборд, отчёт по офферам) для каждой рекомендации или скора показывать, какие факторы учтены: наши метрики + какие внешние источники и по каким странам.

4. **Настройки**  
   В разделе «Внешние данные для аналитики офферов» в Настройках:
   - перечень источников с подсказками «что даёт» и «как подключается»;
   - поля для ключей/URL только для тех источников, которые уже реализованы в коде;
   - возможность включать/выключать категории или отдельные источники, чтобы расчёт оставался предсказуемым.

## Этапы реализации

1. **Документ и подсказки в UI** (текущий шаг)  
   Этот файл + блок в Настройках с описанием источников и способов подключения.

2. **Ключи и флаги в настройках**  
   Добавить в интеграции ключи (например, `news_api_key`), опционально URL для сезонности или выгрузок. По ним бэкенд решает, какой источник вызывать.

3. **Сервис загрузки и кэша**  
   Модуль «внешние данные»: запрос по (оффер, страна, период) → вызовы API/файлов → нормализация в общую схему → кэш (Redis/БД) с TTL.

4. **Интеграция в расчёт прибыльности и рекомендации**  
   Аналитика и оптимизатор принимают внешние сигналы как вход; обновить формулы/промпты и отображение причин в UI.

5. **Дополнительные источники**  
   По мере появления новых API или выгрузок — добавлять в этот список, в настройки (ключ/URL) и в сервис загрузки без смены общей схемы.
