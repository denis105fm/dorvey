# План: Cloaking + внешние ключевые слова для дорвеев

Цель: быстрый выход в поиск, долгоживучесть дорвеев, максимальная конверсия. Ключевые слова — из внешней аналитики по гео, не «от балды».

---

## Часть 1. Система cloaking (бот vs человек)

### 1.1 Принцип

| Кто | Что видит | Зачем |
|-----|-----------|-------|
| **Поисковый бот** (Googlebot, YandexBot, Bingbot и др.) | SEO-версия: полный контент, FAQ, ключевые слова, микроразметка, без агрессивных CTA | Ранжирование, индексация, доверие |
| **Человек** | Конверсионная версия: облегчённый контент, CTA, exit-intent, офферы по geo/device | Конверсия, CR |

Итог: бот индексирует «полезную» страницу, человек получает «продающую».

### 1.2 Архитектура

```
[Запрос] → Nginx/веб-сервер на целевом домене
              ↓
         User-Agent? → is_bot() ?
              ↓                    ↓
           Bot                  Human
              ↓                    ↓
   HTML_SEO (готовый)      HTML_CONVERSION (готовый)
```

**Важно:** HTML для обеих версий генерируется при деплое и кладётся на сервер. Сервер (или небольшой middleware) выбирает, какой файл отдать по User-Agent. Либо: PHP/Node-скрипт на сервере, который читает User-Agent и отдаёт нужный HTML.

### 1.3 Варианты реализации

| Вариант | Описание | Плюсы | Минусы |
|---------|----------|-------|--------|
| **A. Два HTML-файла** | `index.html` (human), `index.seo.html` (bot). Nginx/правила по User-Agent отдают нужный. | Просто, без скриптов | Нужна настройка Nginx на каждом домене |
| **B. PHP/Node endpoint** | Один `index.php`/`index.js`: читает UA, отдаёт нужный HTML из файлов/БД | Гибко, одна точка входа | Требует PHP/Node на сервере |
| **C. Edge (Cloudflare Workers и т.п.)** | На уровне CDN/edge: проверка UA, раздача разного контента | Централизованно | Зависимость от провайдера |

**Рекомендация для Dorvey:** Вариант A — два файла. При деплое генерируем:
- `index.html` — human (в path или root)
- `index.seo.html` — bot

**Nginx конфиг для cloaking** (в `server` блок для домена дорвея):
```nginx
# Cloaking: bots get index.seo.html
map $http_user_agent $cloak_suffix {
    default "";
    ~*(Googlebot|YandexBot|Yandex|bingbot|Slurp|DuckDuckBot) ".seo";
}
# В location / или root:
location / {
    try_files $uri $uri/ $uri/index$cloak_suffix.html $uri/index.html =404;
}
# Или для SPA-style (если всё в одной папке):
# try_files $uri/index$cloak_suffix.html $uri/index.html $uri/ $uri =404;
```
Или PHP/Node: читать User-Agent, отдавать нужный файл.

### 1.4 Содержимое SEO-версии (для бота)

- **Title, meta_description** — те же, что у human (или слегка «чище» под поиск)
- **Content** — полный текст, 600+ слов, закрытие интента
- **FAQ** — PAA/FAQ schema, видимый блок
- **Article/WebPage schema** — микроразметка
- **Без:** exit-intent, агрессивные pop-up, sticky CTA снизу
- **CTA** — одна ненавязчивая ссылка «Узнать подробнее» в тексте
- **Опционально:** дополнительный блок «скрытых» ключевых слов — но **осторожно**: Google бьёт за keyword stuffing и hidden text. Лучше распределять ключи естественно по контенту.

### 1.5 Содержимое Human-версии

- Текущая логика: контент + trust + urgency + comparison + CTA + exit-intent + офферы по geo
- Можно чуть сократить текст для быстрой загрузки и фокуса на CTA

### 1.6 Что нужно в коде Dorvey

1. **`prepare_doorway_html`** — вызывать дважды или с флагом: `for_bot=True` и `for_bot=False`
2. **Шаблоны** — вариант SEO (без exit-intent, минимум CTA) и CONV (текущий)
3. **Деплой** — выкладывать оба файла; конфиг Nginx — в документацию или в deploy-скрипт
4. **`cloaking_rules`** — расширить: `cloaking_enabled`, `bot_patterns` (уже есть `is_bot`), опционально `seo_content_override` если нужен отдельный текст для бота

### 1.7 Риски и ограничения

- Google/Yandex **запрещают** cloaking в Guidelines. Это серый/чёрный метод.
- Риск: manual action, выпадение из индекса.
- Смягчение: SEO-версия должна быть **реально полезной**, не «мусор для бота». Тогда граница размыта (A/B тест контента vs cloaking).

## Часть 2. Ключевые слова из внешней аналитики

### 2.1 Проблема

Сейчас ключи вводятся вручную или импортируются из CSV. Объём (volume) есть в модели `Keyword`, но не заполняется автоматически. Нет привязки: оффер → гео → какие ключи самые высокозапросные в этой гео.

### 2.2 Цель

- Подтягивать ключи из внешних источников по **стране/региону**
- Связывать с **офферами**: оффер с `geo=RU` → ключи с высоким объёмом в RU
- Ниша кампании (или оффера) → семантическое ядро + volume по гео

### 2.3 Источники данных (по приоритету)

| Источник | Что даёт | API / способ | Ограничения |
|----------|----------|--------------|-------------|
| **DataForSeo** | Volume по ключам, по гео, Suggestions, Related | API (платный) | Лимиты, тарификация |
| **SEMrush** | Keyword Magic, volume по country | API (платный) | Дорого |
| **Ahrefs** | Keywords Explorer, volume по country | API (платный) | Дорого |
| **Serpstat** | Keyword research, volume, по гео | API (дешевле) | Меньше покрытие |
| **Google Keyword Planner** | Volume (при наличии рекламного аккаунта) | Google Ads API | Нужен аккаунт |
| **Ubersuggest / Neil Patel** | Базовый volume | API (есть тариф) | Ограниченный набор |
| **Keys.so / Другие агрегаторы** | Агрегация нескольких источников | API | Зависит от провайдера |

**Рекомендация для первой реализации:** DataForSeo — хороший баланс цена/функциональность, есть `keywords_data/google_ads/search_volume/live` и `keywords_data/google_ads/keywords_for_keywords/live` по странам.

### 2.4 Схема: оффер → гео → ключи

```
Campaign
  └── Offers (geo: RU, KZ, BY, …)
  └── Keywords (keyword, volume, region?)

Логика:
1. Оффер с geo=RU → нужны ключи с высоким volume в RU
2. Ниша кампании (из названия, affiliate_url, или отдельное поле "niche") → seed-запрос для подбора
3. Запрос к API: "Дайте топ N ключей по объёму для seed + country=RU"
4. Импорт в Keywords с volume и привязкой region
```

### 2.5 Расширение модели

```python
# Keyword — добавить поля
region = Column(String(10), nullable=True)   # RU, US, etc.
source = Column(String(50), nullable=True)   # "dataforseo", "semrush", "manual"
cpc = Column(Float, nullable=True)           # опционально
```

### 2.6 API-сервис: подбор ключей

**Endpoint:** `POST /api/keywords/suggest-from-external`

**Вход:**
```json
{
  "campaign_id": 1,
  "seed": "кредит наличными",
  "country": "RU",
  "limit": 100,
  "source": "dataforseo"
}
```

**Выход:**
```json
{
  "keywords": [
    { "keyword": "кредит наличными без отказа", "volume": 12000, "cpc": 45.2 },
    { "keyword": "кредит наличными срочно", "volume": 8100, "cpc": 38.1 }
  ],
  "source": "dataforseo"
}
```

Действие: пользователь может выбрать ключи и импортировать в кампанию (с `volume`, `region`).

### 2.7 Автоподбор по офферам

**Сценарий:**
- У кампании есть офферы с разными `geo`
- Пользователь нажимает «Подтянуть ключи по офферам»
- Система: для каждого уникального `geo` в офферах кампании + seed (название кампании или общий запрос) → запрос к DataForSeo
- Результат: батч ключей с `region` и `volume`, предлагаем импорт

### 2.8 Интеграция в генерацию дорвея

Сейчас при генерации: `keyword` берётся из формы (один ключ) или из списка Keywords кампании. Объём не используется.

**Изменения:**
1. При выборе ключа из списка — показывать `volume` и `region`
2. Рекомендация: генерировать сначала дорвеи по ключам с **максимальным volume** для гео офферов
3. В batch-генерации: сортировка ключей по `volume` desc, лимит по гео

## Часть 3. Встраивание в текущий поток генерации

### 3.1 Текущий поток

1. Кампания + Домен + Ключевое слово (ручной ввод или выбор из Keywords)
2. Генерация (AI: title, meta, content, FAQ)
3. Сохранение в Doorway
4. Деплой → один HTML

### 3.2 Новый поток (с cloaking)

1. Кампания + Домен + Ключевое слово
2. **Опция:** Cloaking включён (чекбокс или настройка кампании)
3. Генерация:
   - Один вызов AI (контент общий или слегка адаптированный)
   - Рендер **двух** HTML: `_seo` и `_conv`
4. Сохранение: в Doorway — оба варианта (или два поля: `html_human`, `html_bot`)
5. Деплой → оба файла + конфиг Nginx

### 3.3 Новый поток (с внешними ключами)

1. **Ключевые слова:**
   - Ручной ввод
   - Или: «Подтянуть из DataForSeo» → seed + country → выбор из списка → импорт
   - Или: «Подтянуть по гео офферов» → автоматический обход geo офферов
2. При генерации: выбор ключа из списка (отсортирован по volume)
3. Batch: список ключей сортируется по volume, генерация по приоритету

## Часть 6. Риски и оговорки

1. **Cloaking** — нарушение правил поисковиков. Использование на свой риск.
2. **API лимиты** — DataForSeo и др. считают запросы. Кэширование по (seed, country) обязательно.
3. **Стоимость** — подписки на API keyword research. Учитывать в биллинге/лимитах.
4. **Качество ключей** — volume не гарантирует трафик и конверсию. Нужна аналитика по CR после выхода в топ.

## Итог

- **Cloaking:** бот видит SEO-страницу, человек — конверсионную. Два HTML при деплое, выбор по User-Agent на сервере.
- **Ключевые слова:** подтяжка из DataForSeo (и др.) по seed + country, привязка к гео офферов, импорт с volume, сортировка при генерации.
- **Интеграция:** в генерацию дорвея — опция cloaking, два рендера; в Keywords — блок «Подтянуть из внешних источников» и «По гео офферов».
